# B2B 工作台 · 增值服务卡片列表设计

> 日期:2026-07-28
> 范围:`demo/pda/b2b-workbench.html` 的「增值」Tab 列表区
> 来源需求:用户希望以卡片形式展示"仓库需要操作的单 + 对应的增值服务信息"

---

## 一、背景与业务依据

手册 §3.12.6(来源《B2B增值服务操作手册》)明确:**增值服务按子单粒度操作**——
7 类增值服务(贴外箱标/贴内件标/复核尺寸/复核重量/换箱/换单/清点拍照)的操作起手
都是「扫描子单号」。主单只是子单的归组,不是增值服务的操作对象。

> 证据:操作手册原文「扫描子单号」出现 13 次,覆盖全部 7 类;
> 「整单打印」仅 2 次,指贴标/箱标补打的"子单打印 vs 整单打印"二选一(打印动作范围),
> 非把增值服务标记到主单。

当前 `b2b-workbench.js` 的「增值」Tab 与其他 Tab 共用同一套扁平表格
(单号/分拣码/库位/时间),不展示增值服务详情,也不区分主单/子单。需改造为卡片。

---

## 二、设计决策(已与用户确认)

| 决策点 | 结论 | 理由 |
|-|-|-|
| 改造范围 | **仅「增值」Tab** 用卡片,其他 5 个 Tab(全部/换单/查验/盘点/退仓)保持表格 | 改动最小,聚焦需求 |
| 增值项呈现 | **标签云 chip**,颜色区分状态 | 紧凑,扫一眼看进度,适合多项 |
| 卡片头单号 | **子单号为主 + 主单号为辅** | 增值服务落在子单,操作对象须主显示 |
| 分拣码/库位/时间 | 保留,风格对齐现有表格 | 视觉过渡自然 |

---

## 三、卡片布局(PDA 瘦长屏 ~390px)

```
┌─────────────────────────────────────────┐
│  子单 YTZ526723600100117         09:18  │  子单号(主)+ 时间(右,弱色)
│  主单 YTZ5267236001001                  │  主单号(小字,弱色)
│  [A-03]  A-03-02-05                     │  分拣码标签 + 库位
│  ─────────────────────────────────────  │
│  [贴外箱标 ✓]  [换箱]  [复核重量]       │  标签云:done=主色描边+✓,todo=灰描边
│                                  去处理→ │  整卡可点(:active 反馈)
└─────────────────────────────────────────┘
```

- **chip 状态配色**(克制,遵循规范主色 `#00A99D`):
  - `done`(已完成):主色描边 + 浅主色底 + ✓ + 主色字
  - `todo`(待办):灰描边 + 白底 + 灰字
- **整卡 `:active`** 复用现有按压底色 `#f7f9f9`
- **"去处理 →"** 静态原型,点击只 toast「去处理:增值服务操作页」(不建新页)

---

## 四、数据结构(TASKS 的 vas 项扩展)

现有非 vas 任务保持 `no` 字段不变;vas 项改用 `subNo`/`mainNo` + 新增 `vasItems`:

```js
{
  subNo: 'YTZ526723600100117',   // 子单号(操作对象,主显示)
  mainNo: 'YTZ5267236001001',    // 主单号(归组,附显示)
  sortCode: 'A-03',
  loc: 'A-03-02-05',
  time: '09:18',
  type: 'vas',
  vasItems: [
    { name: '贴外箱标', status: 'done' },   // status: 'done' | 'todo'
    { name: '换箱',     status: 'todo' },
    { name: '复核重量', status: 'todo' },
  ]
}
```

演示数据补充 2-3 条 vas 任务(不同增值组合、不同完成度),让卡片有内容。
`TABS` 里 vas 的 `count` 改为实际条数。

## 五、改动点(3 处,最小化)

| 文件 | 改动 |
|-|-|
| `js/b2b-workbench.js` | ① vas 演示数据扩字段 + 增条;② `renderTasks()` 内 `if (currentTab==='vas')` 分支渲染卡片 HTML(读 subNo/mainNo),其余分支走原表格(读 no)不动 |
| `css/pages.css` | 末尾追加 `/* === B2B工作台·增值卡片 === */`:`.vas-card` / `.vas-card-sub` / `.vas-card-main` / `.vas-card-meta` / `.vas-chip` / `.vas-chip--done` / `.vas-chip--todo` / `.vas-go` |
| `b2b-workbench.html` | **不改**(骨架不变) |

### 筛选复用
现有筛选条(单号/库位)对 vas 卡片同样生效——vas 分支沿用同一套 `filters` 过滤,
匹配字段:单号 → `subNo`(子单号),库位 → `loc`。

---

## 六、不做(YAGNI)

- ❌ 不新建"增值服务操作"详情页(原型阶段,去处理只 toast)
- ❌ 不动其他 Tab / 不动框架层(base.css/layout.js/helpers.js)
- ❌ 不引入主单聚合(与"按子单操作"业务语义冲突)
- ❌ 不区分更多状态(只 done/todo 两态,够用)

---

## 七、验证

1. 浏览器双击 `b2b-workbench.html` 打开
2. 点「增值」Tab → 应见卡片列表(非表格)
3. 卡片头:子单号主显示 + 主单号小字 + 分拣码标签 + 库位
4. 标签云:done 主色+✓,todo 灰色
5. 点卡片 → toast「去处理:增值服务操作页」,按压有底色反馈
6. 切其他 Tab → 仍是原表格,功能不变
7. 筛选条输子单号/库位 → 卡片实时过滤
8. 回归:换单/查验/盘点/退仓 Tab 渲染正常
