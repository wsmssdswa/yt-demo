## 二、演示主链路

1. **主数据**：`费用项` → `销售产品映射` → `客户归属`。
2. **产品价格**：`底价`（OA 审批）→ `公布价 A`（强校验 > 底价）→ `套餐 B–E` → `批量调价`。
3. **客户价格**：`套餐绑定` / `自由价`（低于底价转审批）→ `取价优先级`。
4. **询价**：`新建询价`（AI 识别）→ 详情页依次录成本 → 港前确认 → 销售报价 → 绑定订单形成订单价。
5. **试算/报价单**：`内部试算` → `报价单模板/资料` → 生成 → 预览 → 发布用户中心 → 企微发送。
6. **计费**：`计费单` → 详情看重算与回传 → `改价/勘误` → `报文监控`。

推荐按以下顺序点：

1. 工作台 → 待办进入审批/询价/计费异常；
2. 产品底价 → 公布价（试一下低于底价，会被拦截）；
3. 客户自由价（低于底价 → 提交审批）→ 审批中心通过；
4. 询价详情 `INQ20261022001`：录成本 → 风控 → 报价 → 绑定；
5. 内部试算：切“加拿大 · 无价格”，再点“发起询价”；
6. 报价单预览 `Q20261002`：发布/企微发送；
7. 计费详情 `B202610220001`：重算、查看原始报文；
8. 计费单 `B202610220003`：计费失败 → 去补价。

## 三、已实现的交互

- **价格校验**：公布价 ≤ 底价时实时红框 + 禁止提交；客户自由价低于底价自动转审批。
- **审批**：审批中心可通过/驳回（驳回必须填原因），结果回写底价/公布价/套餐/客户价/改价单。
- **询价状态机**：草稿 → 待成本 → 待风控 → 待报价 → 已报价 → 已绑定；每步写时间线与操作日志。
- **计重计算器**：按客户/产品规则实时计算材积重、单箱进位、整票进位；可增删子箱。
- **取价瀑布**：订单价 → 自由价 → 套餐 E/D/C/B → 公布价，逐层展示命中与不可用原因。
- **试算**：真实按数据计算总费用；无价返回明确错误并支持转询价。
- **报价单**：版式配置、生成/发布、客户视角预览、打印、企微发送。
- **计费**：重算、费用明细、回传状态、原始报文、改价/勘误（零元、USD 多币种）。
- **数据持久化**：改动存在浏览器 localStorage；右上角头像菜单可“重置演示数据”。

## 四、技术约定

- 纯静态、零依赖：不使用 npm、框架、构建工具；`file://` 双击可用。
- 多 HTML 多页面：页面间 `location.href` 跳转。
- 主色 `#00A99D`；字体 `Microsoft YaHei / PingFang SC`。
- 共享层：
  - `css/base.css`：设计令牌、布局、表格、表单、抽屉、弹窗、Toast；
  - `css/pages.css`：页面级业务组件（工作台、价格矩阵、报价单、计重等）；
  - `js/data.js`：演示数据；
  - `js/store.js`：localStorage、查询、计重/计价逻辑；
  - `js/ui.js`：导航外壳、图标、表格、抽屉、弹窗、审批等公共组件。

## 五、待确认口径

原型不把这些写成既定规则，页面上以“待确认 / 示例”标注：

1. **首期范围**：X 系列、整柜是否全部纳入；询价是否不限产品。
2. **审批规则**：底价/套餐/客户价/改价各自由谁审批、金额阈值。
3. **费用项规则专项**：附加费的叠加/取高/互斥是否单独专项。
4. **订单价覆盖**：按当前代码，CCOS 重量勘误会自动覆盖成交价、不校验是否已出账；业务上是否需要拦截待拍板。
5. **多币种**：BMS 按 RMB 汇总、ARS 按签约主体币种；原型仅用 USD 示例，不做汇率换算。
6. **接口契约**：字段、错误码以联调为准；报文类型已按代码核对为 1003 / 1802 + `AddChargeWeight`。
7. **询价单**：OMS/B2B-OMS/PQM/CCOS 四仓暂无“询价单”实现，属于新建能力，状态机需评审确认。

已核对的跨系统结论与影响见 [docs/open-questions.md](docs/open-questions.md)。
